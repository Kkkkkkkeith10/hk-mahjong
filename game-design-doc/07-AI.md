# 07 · AI Player Design

Runs identically server-side (multiplayer fill/takeover) and on-device (單機). Pure Dart inside `mj_core`. Must respect the room's edited FanTable and active modes.

---

## 1. Foundation: 16-tile shanten

`shanten(hand, melds, jokers) → int` — distance to 聽 for 基本形 (5 面子+1 眼) and each 特殊形 (嚦咕/十三么/十六不搭), taking the minimum. Implementation: recursive meld extraction with memoization on (tile-count vector, melds-needed) + upper-bound pruning; jokers = free wildcards consumed greedily in the search (each joker reduces requirement of the best-scoring slot). Performance budget: < 5 ms/hand on低端機 — cached between turns, invalidated on hand change.

Derived: `waits(hand)` (tiles that reach -1/win), `acceptance(hand)` (tiles that reduce shanten, weighted by live count from visible info).

## 2. Decision layers (per difficulty)

**L1 初級 — greedy:** discard = tile whose removal minimizes shanten, tiebreak max acceptance. Claims only if they reduce shanten. 叮 whenever 聽. No defense. (Beatable, fast, good for 新手場.)

**L2 中級 — value & safety:** adds (a) 番 awareness — score candidate end-hands with the ROOM's FanTable; prefers lines with higher expected 番 when shanten-equal (so if the host boosts 清一色 to 500, the AI chases flushes — the editor visibly changes AI behavior, a delightful integration); (b) claim discipline — won't break 門清/門叮 potential for marginal melds; (c) defense — tracks discards/melds/叮 declarations; when an opponent 叮s or shows a big-suit posture and own shanten ≥ 2, switches to safe tiles (genbutsu = tiles in the threatener's river or made 過水; suji-like inference on 16-tile is weak, so lean on river + count data).

**L3 高級 — expectation:** adds 1-ply expectimax on draw outcomes for close discard decisions; claim EV includes tempo (seats skipped); 拉 ledger awareness — plays tighter (folds earlier) against a player it has a large recorded ledger with (protecting the 拉), and hunts 自摸 when holding multiple ledgers; 換牌 mode: passes to maximize post-swap acceptance rather than just dumping isolation.

## 3. Mode adaptations

- **百搭:** shanten/waits joker-aware (§1); discard policy never discards a joker when forbidden (blocked anyway) and values jokers ≈ best live wait; L2+ recognizes 淨百搭 bonus if configured (may hold a joker-free line when close).
- **換牌:** selection per level: L1 most-isolated tiles; L2 worst-suit block respecting same-suit constraint; L3 acceptance-optimized.
- **叮 decision (L2+):** declare only if wait count ≥ 2 or wait quality high or 即食 likely; considers that 叮 reveals info and locks the hand; L1 always declares (creates teachable moments).
- **花糊 choices:** claim instantly at L1; L2+ compares instant value vs hand potential.

## 4. Behavioral polish

Humanized timing: decisions delayed 0.8–2.5 s (level-scaled, capped by room timers) so AI doesn't feel robotic; occasional "think" pause on big claims. AI seats show robot badge + level; use distinct avatar set (茶餐廳 mascots) and the standard voice packs. AI never uses information a player couldn't have (no wall/hand peeking — enforced by giving AI the same filtered view interface as clients).

## 5. Testing & tuning

Self-play harness (headless, 10k+ hands/config): win-rate matrix across levels (target: L3 > L2 > L1 with ≥ 8% separation), 詐-line checks (AI never attempts illegal intents), FanTable-sensitivity test (boosting a 番種 measurably shifts L2/L3 behavior), performance profiling on min-spec device. Balancing knobs exposed in config, not code (Remote Config for server, asset for local).
