# mj_core

Pure-Dart rules engine for 港式台牌. Shared verbatim by the Flutter client
(offline play), the Cloud Run game service (online play), and the AI players —
one implementation, zero divergence (see `../game-design-doc/08-INTEGRATION.md`).

## Running the tests (on your machine)

The Cowork sandbox has no Dart SDK, so the tests were written here but must be
run locally:

```bash
cd mj-game/mj_core
dart pub get
dart test
```

Expected: **all green on first run.** If `wall_test.dart` fails, the Dart code
diverges from the frozen determinism contract — do not "fix" the fixtures;
fix the Dart. Likewise `fans_golden_test.dart` (414 scoring cases),
`settle_golden_test.dart` (8 ledger lifecycles), and `game_golden_test.dart`
(24 full self-play games, event-log bit-for-bit): a red test means a port bug
in `lib/src/`, never a fixture bug. Regenerate fixtures only when the Python
reference itself changes: `cd ../ref_engine && python3 gen_fixtures.py`.

## Determinism contract

Seed ⇒ wall permutation must be identical everywhere, forever (replays,
fairness audits, and the offline/online parity invariant all depend on it).
The contract is: SplitMix64 (64-bit wrapping, VM/AOT only — do not compile
this package to JS), `nextBounded(n) = (next() & 0x7FF…F) % n`, top-down
Fisher–Yates, and the exact canonical tile order in `Tile.canonicalSet`.

`tool/gen_golden.py` is the reference implementation; it generated
`test/fixtures/wall_golden.json` (4 seeds × joker variants + raw RNG check
values). Any change to the contract requires regenerating fixtures **and**
invalidates all stored replays — so don't.

## fan_table.json

Loaded from `../data/fan_table.json` (schema `fan_table/v1`, 153 entries,
transcribed from 總例 p.18 at 300 dpi on 2026-07-07). The loader validates
ids, references, detector keys, and the settlement block on load and throws
`FormatException` on any defect. Open rule questions are tracked in
`../data/VERIFICATION-fan-table.md` (VERIFY-1…10).
